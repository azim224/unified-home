# «Единый дом» — плагин Амалии

Один дом: устройства, сцены с планом и подтверждением, локальная сеть Амалии
и пробный арбитраж «кто отвечает». Облако не участвует.

```
unified-home/
├── android/    native-плагин Amalia V3 (Kotlin, Compose, подписанный platform.json)
└── README.md   этот файл
```

ПК-версия того же плагина живёт рядом с хостом:
`/root/amalia-pc/examples/plugins/unified-home/` (Python, инструменты + веб-панель).
Формат плагинов на ПК другой — питоновский модуль вместо DEX, — поэтому общий
у них не код, а модель: устройства, сцены, план, честные статусы, UDP-меш.

## Общий дом v2

Android и ПК теперь используют один аутентифицированный протокол: явное
создание/присоединение по секретному приглашению, участники с сервисами,
удалённый каталог → план → применение с результатом.

**Начни здесь:** [SHARED_HOME.md](SHARED_HOME.md) — порядок объединения устройств,
полномочия участников, ограничения безопасности и что пока не реализовано.
[HOME_PROTOCOL_V2.md](HOME_PROTOCOL_V2.md) — точный сетевой контракт.

## Что общего у двух реализаций

| Понятие | Правило |
|---|---|
| Устройство | `light` / `switch` / `climate` / `media` / `cover` / `sensor`, комната, адаптер |
| Адаптер | `sim` (симулятор), `http` (свой мост), `homeassistant` (REST + проверка состояния) |
| Сцена | набор шагов, ничего не делает без применения |
| План | снимок «до → после», пропуски и блокировки; живёт 3 минуты |
| Исполнение | по каждому устройству: `confirmed` / `sent` / `unknown` / `failed` / `skipped` |
| Сеть | v2: HMAC-аутентификация, announce раз в 5 с, диагностический vote, RPC catalog/plan_scene/apply_plan |
| Арбитраж | побеждает больший счёт, при равенстве — больший приоритет роли, затем id |

«Отправлено» никогда не выдаётся за «подтверждено». После `unknown` команда
не повторяется вслепую: сначала читается состояние.

## Android (`android/`)

Native-плагин V3: настоящий Compose-экран, 12 инструментов `home_*` для модели,
правила в системный промпт. Собирается против точного `amalia-native-sdk.zip`
этой сборки хоста, подписывается P-256 ключом издателя.

Подробности — [android/README.md](android/README.md): сборка, упаковка,
контракт HTTP-моста, ограничения (cleartext в LAN, MulticastLock, отсутствие
доступа к аудиобуферу хоста) и чек-лист проверки на устройстве.

## ПК

Плагин уже работает и покрыт тестами хоста (`tests/test_unified_home_plugin.py`,
`tests/test_audio_devices.py`). Даёт инструменты `home_*`, REST-панель
`/api/plugins/unified-home` и раздел «Дом» в веб-интерфейсе.

## Микрофон на ПК (телефон как микрофон)

Экран настроек: список всех устройств ввода, отметки «телефон» и
«по умолчанию», обновление списка, проба уровня для выбранного устройства.

Что сделано ради телефона-микрофона:

- **id устройства PortAudio больше не голый индекс.** Индекс сдвигается,
  когда приложение с телефоном подключается или отваливается, — сохранённый
  выбор молча указывал бы на другой микрофон. Теперь id — `pa:<индекс>:<отпечаток имени>`,
  и при сдвиге устройство находится по отпечатку. Старые id (`pa:4`) работают.
- **«Проверить уровень» проверяет выбранное в списке устройство**, даже если
  настройки ещё не сохранены: `GET /api/audio/level?device=…`.
- **Список обновляется сам**, пока открыты настройки (раз в 4 секунды) —
  подключённый телефон появляется без нажатий.
- **Пропавшее устройство видно**: сохранённый, но отключённый микрофон
  показывается отдельным пунктом «не подключено», а не подменяется другим.

## Чего пока нет (честно)

- **Арбитраж не врезан в голосовой конвейер хоста.** Плагин реализует
  протокол и выбор победителя, но «услышал — проголосовал — начал слушать»
  требует хука в момент детекции речи, а его у плагина нет: микрофон и VAD
  принадлежат хосту. Счёт близости (RMS × уверенность VAD + контекст экрана)
  должен считаться там же, где читается аудиобуфер.
  Следующий шаг для ПК — вызов `mesh.arbitrate(score)` из `handle_voice`
  до старта распознавания; для Android — соответствующий хук в хосте.
- **Android JAR/DEX не скомпилированы**: exact-host native SDK отсутствует.
  Синтаксис Kotlin проверен, но нужна компиляция в CI/у разработчика.
- Старый **handoff отключён**. Вместо него v2 remote catalog/plan/apply с общим
  ключом дома и одноразовыми планами; HMAC не шифрует LAN-трафик.
- Самоподписанные HTTPS-сертификаты не принимаются: «доверять всему» — не
  решение для дома.
