# «Единый дом» — native-плагин Amalia V3

Один дом: устройства, сцены с планом и подтверждением, локальная сеть Амалии
(mDNS-независимый UDP-меш) и арбитраж «кто отвечает».

Это **native**-плагин: настоящий Compose-экран, инструменты для модели и
Android-context. Он собирается против точного SDK конкретной сборки хоста,
подписывается ключом издателя и активируется как `android-dex` пакет.

```
android/
├── native-plugin.json        манифест автора (packageId, entryPoint, ABI)
├── build.gradle.kts          compileOnly против экспортированного native SDK
├── settings.gradle.kts
└── src/main/kotlin/org/amalia/unifiedhome/
    ├── Entry.kt              точка входа + AmaliaPlugin + вклады
    ├── Domain.kt             устройства, сцены, планы, состояние, хранилище
    ├── Engine.kt             планирование, исполнение и повторная проверка
    ├── Transport.kt          переходники: sim / HTTP-мост / Home Assistant
    ├── Mesh.kt               сеть общего дома, участники и RPC
    ├── HomeLink.kt           общий wire-протокол v2, HMAC и строгий JSON
    ├── Tools.kt              инструменты дома для LLM
    ├── Screen.kt             экран на стекле и токенах хоста
    └── Copy.kt               тексты на девяти языках
```

## Что умеет

| Слой | Поведение |
|---|---|
| Устройства | `light`, `switch`, `climate`, `media`, `cover`, `sensor`; комнаты; состояние с моста |
| Сцены | план по текущему состоянию → подтверждение → исполнение → сверка по каждому устройству |
| Честность | `confirmed` / `sent` / `unknown` / `failed` / `skipped`; «готово» только при `confirmed` |
| Сеть | общий дом v2, HMAC, явное членство, каталог/план/применение на другом узле |
| Модель | 12 инструментов `home_*` + правила в системный промпт |
| Экран | сводка, сцены, комнаты, сеть, журнал; загрузка / пусто / ошибка / офлайн |

## Сборка и установка

Нужен `amalia-native-sdk.zip` из CI **этой** сборки хоста
(workflow *Native SDK distribution*, артефакт `amalia-native-sdk`), JDK 17,
D8 из Android build-tools и приватный P-256 ключ издателя.

```sh
# 1. распаковать SDK рядом с проектом и указать его в native-plugin.json ("sdk")
unzip amalia-native-sdk.zip -d amalia-native-sdk

# 2. проверить манифест, ABI и отсутствие лишнего в пакете
python3 /path/to/amalia-3.0/tools/native_plugin.py validate --project android \
  --sdk "$PWD/amalia-native-sdk"

# 3. собрать тонкий JAR (никаких fat-jar: классы хоста поставляет хост)
android/gradlew -p android jar

# 4. подписать и упаковать
python3 /path/to/amalia-3.0/tools/native_plugin.py package --project android \
  --private-key ~/publisher-keys/unified-home.pem --key-id unified-home-1 \
  --d8 /path/to/android/build-tools/35.0.0/d8 \
  --output dist/org.amalia.unifiedhome-1.0.0.amaliaplug
```

Для подписи используйте постоянный ключ и фиксированный `keyId`, описанные ниже.

Локальная сборка APK не нужна и запрещена в этом репозитории.

## Сборка в GitHub Actions

Workflow `.github/workflows/build.yml` в этом репозитории запускается при push,
PR, теге `v*` и вручную. В secrets репозитория нужен `AMALIA_TOKEN` с правом
чтения `azim224/amalia-3.0` (для fine-grained PAT — Contents: read).
Внешние fork PR не получают этот секрет и не могут собрать приватный хост.

Готовый артефакт из `native-sdk.yml` больше не требуется: workflow сам
экспортирует exact-host SDK задачей `:app:exportNativeSdk`, проверяет его хеши
и манифест плагина, компилирует JAR и упаковывает DEX. APK не собирается.
По умолчанию используется ветка хоста `azim224`, содержащая native SDK V3;
ветка `v2.0` не содержит экспортера и для этого плагина не подходит.
При ручном запуске `host_ref` позволяет выбрать конкретный commit/tag
совместимого установленного хоста. Для push/tag сборок при необходимости
поменяйте fallback `azim224` в workflow.

Артефакт `unified-home-plugin` содержит:

- `org.amalia.unifiedhome-1.0.0.amaliaplug` — подписанный пакет;
- `publisher-public.pem` — публичный ключ для pin в хосте;
- `publisher-info.txt` — publisher, точный keyId, fingerprint DER SHA-256 и порядок установки;
- `host-commit.txt` — commit хоста, против которого экспортирован SDK;
- `host-sdk-config.patch` — изменение конфигурации SDK в CI-копии хоста:
  для API 37+ явно задаётся minor `0` и путь экспортера `android-37.0`,
  поскольку Google не публикует пакет с именем `platforms;android-37`.
  Также сохраняются `.kotlin_builtins` при нормализации JAR в экспортере:
  без этих метаданных Kotlin не распознаёт базовые типы стандартной библиотеки.
  Исходники API хоста и ABI при этом не меняются.

В CI-копии упаковщика также разрешены Kotlin-имена классов с дефисом;
патч принимает как старый, так и уже исправленный валидатор. Это не меняет
загрузчик установленного хоста (см. ниже).

Теги `v*` публикуют эти же файлы, включая оба публичных файла издателя,
в GitHub Release после успешной сборки. Кроме `AMALIA_TOKEN`, необходим
постоянный `UNIFIED_HOME_SIGNING_KEY`, как описано ниже.

## Постоянный ключ издателя и установка CI-пакета

Один раз **локально**, вне checkout репозитория, создайте ключ P-256:

```sh
umask 077
mkdir -p ~/publisher-keys
# Выполнить только один раз; не перезаписывать существующий ключ.
openssl ecparam -name prime256v1 -genkey -noout \
  -out ~/publisher-keys/unified-home.pem
```

Сохраните резервную копию приватного ключа. Не коммитьте его, не публикуйте
и не прикладывайте к артефактам. В Settings → Secrets and variables → Actions
репозитория, где запускается workflow, создайте secret
`UNIFIED_HOME_SIGNING_KEY` с **полным PEM** этого приватного ключа. Используйте
тот же ключ для следующих сборок, а не генерируйте новый при каждом запуске.
В repository variables задайте постоянный `UNIFIED_HOME_KEY_ID`, например
`unified-home-1` (это значение по умолчанию). `keyId` — точная строка,
а не fingerprint; не меняйте её между обновлениями без явной ротации.
При использовании обоих workflow настройте одинаковые ключ и ID в обоих
репозиториях. Без secret CI останавливается до компиляции SDK; случайного
резервного ключа нет. Проверяется, что ключ — EC P-256.

В артефакте `unified-home-plugin` рядом с `.amaliaplug` находятся
`publisher-public.pem` и `publisher-info.txt`: publisher `org.amalia`, точный
`keyId`, SHA-256 публичного ключа в формате DER и порядок установки. Приватного
ключа в артефакте нет. Fingerprint можно пересчитать без приватного ключа:

```sh
openssl pkey -pubin -in publisher-public.pem -outform DER | openssl dgst -sha256
```

1. Сверьте происхождение артефакта и fingerprint. Если сохранён старый/неверный
   pin, удалите его для `org.amalia` и соответствующего `keyId`.
2. Закрепите `publisher-public.pem` для `org.amalia` с **точным `keyId` из
   `publisher-info.txt`**.
3. **Полностью остановите процесс хоста Amalia** кнопкой применения ключей или
   через Android → Приложения → Amalia → Остановить принудительно, затем откройте
   приложение заново и импортируйте `.amaliaplug` из того же артефакта.
   Уход с экрана или сворачивание приложения не обновляет доверие.
4. Подтвердите review разрешения `android.native` и digest `platform.json`,
   затем активируйте пакет. Установка не переписывает выбор пользователя молча.

**Уже скачанный пакет с `keyId = ci-ephemeral`** требует публичный ключ
**именно той сборки**, которой он подписан. Новый постоянный ключ, ключ другого
запуска или изменение только ID не сделают старую подпись корректной. Если
публичный ключ той сборки недоступен, используйте заново подписанный пакет с
постоянным ключом и его публичные файлы.

**Совместимость загрузчика:** Kotlin генерирует DEX/JVM-имена с дефисом (`-`),
например при mangling value classes. Нужен обновлённый **хост** с исправлением
проверки таких DEX-имён. CI-патч валидатора упаковщика разрешает собрать пакет,
но не обновляет установленный хост: одна переупаковка плагина не исправит
старый загрузчик. Установите исправленный хост и используйте его exact-host SDK.


## Реальная интеграция с железом

Плагин говорит с двумя видами мостов.

**HTTP-мост** (свой сервер, ESP, Raspberry Pi):

```
GET  {address}?device={id}            → {"state": {...}}
POST {address}                        → {"state": {...}}  (необязательно)
     тело: {"device":"…","action":"on","params":{"brightness":40}}
     заголовок: Idempotency-Key: <token:шаг>
     заголовок: Authorization: Bearer <токен> (если задан)
```

Ответ без `state` считается `sent` — команда принята, подтверждения нет.

**Home Assistant** (`adapter = homeassistant`): адрес, `entity_id`, токен.
После вызова сервиса плагин перечитывает `api/states/<entity>` и сравнивает
с ожидаемым состоянием: «команда ушла» и «лампа действительно включилась» —
разные вещи.

Секреты (токен моста, токен HA) лежат в приватном каталоге приложения
(`filesDir/unified-home/state.json`) и никогда не попадают ни в интерфейс,
ни в ответы инструментов.

## Ограничения, о которых честно

- **Cleartext HTTP.** Хост собран с `targetSdk 36` и не содержит
  `networkSecurityConfig`; плагин не может изменить манифест. Поэтому
  `http://` в локальной сети идёт через собственный сокетный клиент
  (`Transport.kt`), а `https://` — системным клиентом с проверкой сертификата.
  Самоподписанные сертификаты не принимаются: «доверять всему» — не решение.
- **MulticastLock.** Нужен `CHANGE_WIFI_MULTICAST_STATE`, которого у хоста нет.
  Плагин пробует захватить блокировку и, если не вышло, показывает это, а не
  делает вид, что сеть всегда доступна. UDP зависит от LAN/firewall/Android;
  в глубоком сне пакеты могут теряться.
- **Счёт близости для арбитража** считает вызывающая сторона: у плагина нет
  доступа к аудиобуферу хоста. Плагин реализует голосование и выбор
  победителя (счёт → приоритет роли → id), а не захват микрофона.
- **Старый handoff отключён.** В v2 все пакеты проверяются по общему ключу дома;
  RPC ограничен каталогом, планированием и применением одноразового плана.
  HMAC не шифрует сообщения и не разделяет права участников. Подробности:
  `/root/unified-home/SHARED_HOME.md`.
- **План живёт 3 минуты.** Старый план описывает уже другой дом.
- **Пакет не приносит ресурсов.** Строки локализованы в коде (`Copy.kt`),
  иконки — из векторного набора хоста (`iconName = "lamp"`).

## Что проверить на устройстве

1. Активация пакета и появление вкладки «Дом» в навигации.
2. Планирование и применение сцены: `confirmed` для симуляторов.
3. HTTP-мост в LAN (свой сервер) — статус `confirmed` или `sent`.
4. Home Assistant: неверный токен → `failed`, верный → `confirmed`.
5. Создать дом на одном устройстве, явно присоединить второе приглашением;
   `home_mesh` видит обоих. Проверить remote catalog → plan → apply. Чужой дом
   и v1 не должны появляться. Голосование — только диагностика.
6. Выключение плагина: экран исчезает из навигации, mesh останавливается,
   сокет закрыт, корутины отменены.
7. Повторное включение и обновление пакета: состояние дома сохраняется.

## Исправления и проверка (2026-11-07)

- Хранилище пишет через Android AtomicFile. Ошибки не выдаются за сохранение;
  повреждённый файл не заменяется демо-данными. Пустой сохранённый дом остаётся пустым.
- Параметры проверяются по возможностям устройства, диапазонам и конечности чисел.
  Неоднозначное имя не выбирает случайное устройство.
- При применении плана состояние читается снова; изменившийся дом требует нового
  плана. Toggle разрешается в явный on/off по прочитанному состоянию.
- HTTP-мост передаёт заданный токен при чтении и записи. Неполные/слишком большие
  HTTP-ответы отклоняются. Home Assistant unknown/unavailable не считаются off.
- Детали доступны отдельно от переключателя. Сохранение/удаление завершаются
  до закрытия формы; ошибки и результаты команд видны; токен скрыт маской.
- Gradle wrapper включён. Исходники синхронизированы с CI-копией
  `amalia-3.0/examples/native/unified-home`. APK локально не собирался.

Проверен синтаксис всех Kotlin-файлов Kotlin PSI parser (0 ошибок) и сопоставлены
используемые API с исходниками хоста. **Это не компиляция JAR/DEX**: exact-host
native SDK отсутствует. Подписанный пакет, активация, работа с железом, внешний
вид и доступность на телефоне пока не проверены.
