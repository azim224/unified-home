# Распределённая Амалия: Android ↔ Android, ПК необязателен

Обновление 2026-11-08. Это описание реализации и её границ, не утверждение о проверке на реальных телефонах.

## Работа без ПК

Каждый телефон содержит каталог дома, адаптеры устройств, планировщик сцен,
координатор ролей, зашифрованный RPC и подключение к собственным LLM/STT/TTS.
Обнаружение и связь — напрямую внутри LAN. Центральный сервер на ПК не нужен.
Минимальный ID среди живых участников выбирает контрольный координатор; роль
мозга выбирается отдельно. ПК — такой же необязательный участник, не сервер.

- `HomeRouting` передаёт текст выбранному мозгу через AES-256-GCM; на мозге
  `AIOrchestrator.processHomeRequest` использует существующий цикл инструментов,
  честные результаты и разрешения ОС, без локальной озвучки и повторного forwarding.
- Инструмент `home_private_context` позволяет модели запросить конкретный контекст
  одного узла или до восьми узлов. Передаются сохранённые сводки, ограниченные
  фрагменты последних сообщений и описания инструментов; не ключи настроек,
  произвольные файлы, экран или сырой аудиопоток. Контекст помечен недоверенными данными.
- Готовый ответ можно передать выбранному устройству для TTS/воспроизведения.
  Ошибка динамика не вызывает повторное выполнение команды. Полученный текст сохраняется.
- При ручном выборе слушателя проигравшие устройства запрашивают его активацию
  по зашифрованному каналу; request ID общего раунда защищает от повторного старта.
  Приёмник проверяет локальное согласие, Android microphone permission,
  wakeWordEnabled, прикреплённый экран ассистента и отсутствие занятого разговора.
  `listening_requested` означает резервирование, не доказательство начала записи.
- Плагин объявляет BackgroundContributor DATA_SYNC при членстве в доме; foreground
  поддерживает сетевую доступность, но не отменяет ограничения Android на микрофон.

## Локальные разрешения

Четыре независимых выключенных по умолчанию переключателя на каждом устройстве:
`shareContext`, `allowBrain`, `allowSpeaker`, `allowListener`. Настройки сохраняются
проверенным commit; смена generation отменяет кооперативную текущую работу.
Модель/другой узел не могут включить эти разрешения. Общий ключ даёт членство,
но не включает доступ к контексту/модели/динамику/микрофону автоматически.

Выбор мозга и говорящего работает для текста и STT. Локальные явные настройки
текстовой маршрутизации имеют приоритет над настройками контрольного узла.
Для акустического арбитража явный выбор любого узла превосходит громкость;
конфликтующие настройки не должны произвольно назначать победителя.

## Общий план

`home_plan_dispatch`: до 64 сцен `{id?, node?, scene, depends_on?}`. Если node
не указан — ручной executor или self. Проверяются циклы, неизвестные зависимости,
повторные IDs, пересечения устройств между сценами, session/deadline/generation.
`home_apply_dispatch` запускает независимые готовые ветви с максимум четырьмя
слотами, сериализует один узел, пропускает зависимые от неуспешных шагов.
Отката общей транзакции нет. Планы одноразовые, без автоматических повторов.

## Wire

В существующем HMAC-конверте v2 новые `secure_request` / `secure_result`:
HKDF-SHA256 от household key с отдельным label, AES-256-GCM, случайный nonce
12 bytes, AAD привязывает дом, стороны, сессии, request ID, время и timeout.
Объявление `secure_version=1`. Операции/аргументы/ответы зашифрованы; метаданные видны.
Старый scene RPC не изменён. Plaintext fallback запрещён.
Полный JSON plaintext ≤8192 UTF-8 bytes, внешний пакет ≤16384 bytes. Крупные
запросы отклоняются до отправки, слишком длинный текст ответа явно сокращается.
UDP single-shot: потеря ответа после действия означает неизвестный исход, не retry.

## Оставшиеся ограничения

- Автоматическая оценка — энергия PCM, не физическое расстояние. Калибровки
  микрофонов и устойчивого подавления фонового шума между разными моделями нет.
- Отдельный executor, отличный от мозга, поддерживается явными распределёнными
  сценами. Произвольная пересылка любого host tool на третий узел не добавлена:
  такая конфигурация обычного запроса явно отклоняется вместо тихого локального действия.
- Контекст ограничен по объёму/типам; медиа-сессии Bluetooth/история музыки,
  экран, камера, произвольные файлы и бинарное аудио не экспортируются.
- ТВ-адаптер, PC always-on wake-word, интернет/NAT traversal, гарантии отсутствия
  двух ответов при partition сети и durable дедупликация после process death отсутствуют.
- Для remote listener экран ассистента и wakeWordEnabled должны быть доступны.
  Фоновый DATA_SYNC не даёт Android права скрытно включать микрофон.
- ПК AES требует установленный cryptography. Если его нет, secure_version=0 и
  приватная функция честно недоступна; Android↔Android от этого не зависит.

## Проверки

- Kotlin PSI всех исходников host и plugin: 0 синтаксических ошибок.
- Прямой JVM type-check actual SecureHome/HomeLink/HomeRouting/HomeSharing/Mesh/
  Coordination/Domain/Engine/Transport + actual Tool.kt: успешен с явно обозначенными
  Android/HostServices/JSON harness adapters. Это НЕ Android/Compose full build.
- Actual Kotlin JDK AES ↔ actual Python secure.py: обе стороны, Unicode,
  rejection modified AAD/ciphertext/tag/extra field. Отчёты `build/home-verification/`.
- Существующие тесты ПК: 71 passed, JS syntax clean, локальные grants API проверены.
- APK не собирался. Физические Android↔Android/ПК, микрофоны, колонки, UI и HA
  требуют проверки на устройствах. Exact-host SDK и обновлённый host необходимы
  для нового native-плагина; старый установленный host не получит API от переупаковки.
