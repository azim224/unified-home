# Один дом для всех Амалий — v2

## Для чего

Телефон, ПК и другие поддерживающие v2 устройства явно вступают в один дом.
Каждое объявляет свои возможности и остаётся владельцем своих устройств/сцен.
Другая Амалия может узнать каталог и попросить построить/применить план сцены.
Это распределённый дом без обязательного центрального сервера, не копирование
всех настроек/истории между устройствами.

## Как объединить устройства

1. Обновить плагин на всех устройствах. Старый v1 несовместим и не принимается.
2. На первом устройстве открыть **Дом → Сеть → Создать дом**.
3. Нажать **Показать приглашение**. Оно содержит секретный ключ дома.
4. На остальных устройствах в разделе сети вставить приглашение в скрытое поле
   и нажать **Присоединиться**. Не передавать приглашение в чат/LLM.
5. Использовать одну локальную сеть и UDP-порт (по умолчанию 47654). Через несколько
   секунд появляются участники с платформой и сервисами. Wi-Fi client isolation,
   firewall, VPN или Android battery saver могут мешать обнаружению.
6. На ПК действия членства разрешены только из локального интерфейса на
   `http://127.0.0.1:<порт>` или `http://localhost:<порт>`: доступ по LAN специально
   не даёт права экспортировать ключ/менять дом. У хоста нет отдельной login-системы;
   локальный процесс имеет те же полномочия, что пользователь ПК.

Приглашение бессрочное. Все участники с общим ключом равноправны. Выход не отзывает
ранее выданные приглашения. Чтобы исключить скомпрометированное устройство,
нужно создать новый дом и вручную присоединить только доверенные устройства.

## Как Амалии помогают друг другу

Инструменты на Android и ПК:

- `home_mesh` — участники текущего дома и объявленные сервисы.
- `home_remote_catalog(node)` — устройства и сцены на выбранном узле, без токенов
  мостов, адресов, истории и произвольных состояний адаптеров.
- `home_remote_plan(node, scene)` — только план, без управления железом.
- `home_remote_apply(node, token)` — применение после явного согласия человека;
  результат содержит реальные статусы отдельных шагов.

Пример: человек разговаривает с телефоном; сцена «Тихий вечер» хранится на ПК,
рядом с мостом домашней техники. Телефон читает каталог ПК, получает план,
объясняет изменения и после согласия отправляет одноразовый токен обратно ПК.
При потере ответа результат **unknown**, а не «готово»; слепых повторов нет.

Токен привязан к запросившему узлу и его сессии, текущему дому и сессии получателя,
живёт максимум три минуты, потребляется до исполнения. Смена дома/сессии делает
его недействительным. Произвольного вызова инструментов/команд shell по сети нет.
Явное согласие перед apply — правило UI/ассистента: общий ключ сам по себе не
доказывает факт согласия, доверенный участник технически способен вызвать RPC.

## Защита и приватность

- Ключ 256 бит, HMAC-SHA256 проверяет принадлежность к дому и целостность пакета.
- Подписаны точные байты тела; timestamp ±60 с, nonce/session, bounded replay cache.
  На устройствах должно быть корректное время.
- Ответ связан с конкретными узлом, сессией, операцией и request_id.
- Запросы одноразовые, без автоматических повторов; ограничены размер и параллелизм.
- **HMAC не шифрует трафик.** Наблюдатель LAN может читать названия и планы;
  аудио/история/ключи мостов не рассылаются. Для недоверенной сети этот этап недостаточен.
- Хранилище ключа — приватный каталог приложения, без обещания аппаратного keystore.

## Что ещё НЕ реализовано

- Общий голосовой ход: «все услышали — отвечает одна Амалия»; голосование остаётся
  диагностикой, не связано с VAD/микрофоном. Нужен отдельный контракт хостов.
- Потоковое аудио, перенос разговора и общей памяти, NAT/интернет-туннели,
  автоматическая репликация каталога и Android always-on background service.
- Индивидуальные права/отзыв одного участника и шифрование сообщений.
- Автоматический запуск сетевого runtime ПК без обращения к плагину и интеграция
  его остановки с переключателем хоста. Сейчас сеть ПК запускается при обращении
  к панели/инструментам, выход из дома явно прекращает участие в обмене.
